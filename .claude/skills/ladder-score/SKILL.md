# ladder-score

[docs/ladder.md](../../../docs/ladder.md) の判定文を、実際のリポジトリに当てる。

出すのは5軸の点と、**次に上げる1軸**である。総合点も順位も出さない。平均を取ると凸凹が
消えて、次に何をするかが出なくなる。

**判定文を暗記や印象で当てない。** 各セルには「読むもの」が書いてある。それを開き、
開いた結果を根拠として引く。根拠を引けない軸は点を付けず、未観測として残す。

## 1. 対象と範囲を決める

採点する人と、証拠を取る期間を確認する。期間の既定は直近3か月とする。

```bash
git log --author="<対象>" --since="3 months ago" --oneline
gh pr list --author "<対象>" --state merged --limit 30
```

コミットが1本も出てこないなら、その時点で止めて対象の指定を確認する。
名前の綴りが違うだけのことが多い。

## 2. 型が入っているかを先に見る

判定文は配られた型の置き場を名指ししている。**その置き場が無いリポジトリでは、
対応する判定文は誰に対しても偽になる。** 人の点ではなく、型の不在として報告する。

```bash
ls PLAN.md JUDGE.md docs/guarantees.md docs/ops/ .github/workflows/ 2>&1
```

無い置き場があれば、[docs/adapt.md](../../../docs/adapt.md) の対応表で読み替え先を探す。
読み替え先も無ければ、その判定文は落として採点する。落としたことは結果に書く。

## 3. 軸ごとに、下から真偽を見る

L2 の判定文から始め、真なら L3 へ進む。**偽になった手前がその軸の点**である。

各判定で必ず次の3つを揃える。

- **判定文**（`docs/ladder.md` からそのまま引く）
- **読んだもの**（ファイルパス、PR 番号、コミット）
- **真偽と、そう言える理由**

理由が「全体的に」「おおむね」で書けてしまうなら、まだ読んでいない。

B 軸は対象者の PR の粒度と裁可の残り方から読む。

```bash
gh pr view <番号> --json title,body,commits --jq '{title, body, n: (.commits|length)}'
```

## 4. 未観測を点で埋めない

証拠が出てこない軸は「未観測」と書く。0 でも L1 でもない。

機会が無くてやっていないことを低い点にすると、育成では打つ手を間違え、選考では取り逃す。
未観測は、育成では機会を配れば分かる軸、選考では面接で聞く軸を指す。

## 5. 次に上げる1軸を決める

**最も低い軸を取る。** 未観測は選ばない。同点が並んだら、案件が先に要求する側を取る。

決めたら、その軸を上げるために回す手順を1つ挙げる。教育メニューを別に作らない。
型を回して出てくる成果物が、次の採点の証拠になる。

## 6. 結果を書く

書式は [reference/scoresheet-template.md](reference/scoresheet-template.md) にある。

**既定では対話に出すだけで、ファイルに書かない。** 採点結果は個人の評価であり、
置き場と実名の扱いを決めていないリポジトリに残すと、後から動かせなくなる。
残すよう指示されたときだけ、指定された場所に書く。

## 同じ段階に複数人が止まっているとき

人ではなく型を疑う。

L2 の判定文は、型が実際に強制するものだけで書いてある。型を理解した人が L2 に届かないなら、
判定文か型のどちらかが間違っている。この場合に直すのは型の側であり、
指摘は人の採点結果ではなく `docs/ops/` に対して出す。
