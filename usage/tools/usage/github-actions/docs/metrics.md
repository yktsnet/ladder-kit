# 指標の定義

[README.md](../README.md) と [workflows.md](../workflows.md) に出す項目について、何を数え、何を数えないかを定める。

## 集める項目

| 項目 | 数えるもの | 数えないもの |
|---|---|---|
| 分数 | ジョブ1つごとの実行時間を1分単位で切り上げて足したもの。再実行した回のジョブも数える。Windows は2倍、macOS は10倍にする。無料枠はこの倍率で減る | public リポジトリの分と、self-hosted runner の分。どちらも課金されない |
| 回数 | ワークフローが実行された回数。起動のきっかけ（`pull_request`・`push`・`schedule` など）ごとに分ける | 再実行。1回の実行の中でやり直した分は、回数ではなく分数に入る |
| 1回あたりの分数 | 分数を回数で割ったもの | |
| 日付 | ワークフローの実行が作られた日本時間の日付 | |

Billing の数字とは数分の差が出る。Billing は日付の区切りが日本時間と9時間ずれるので、月の境の前後では
さらに食い違う。請求額は Organization の owner が Settings → Billing で確かめる。

## 見込みと段

| 項目 | 出し方 |
|---|---|
| 段 | 無料枠を超えた額で区切った、月の分数の目安。無料枠（2,000 分）、5 ドル、10 ドル、15 ドル（予算）の4つを置く。各段の分数は、無料枠に超過額 ÷ 1分 0.008 ドルを足して出す |
| 1日あたりの目安 | 各段の分数を、その月の暦日の数で割ったもの。課金は土日も含めた月の合計で決まる |
| 月末の見込み | 今月の累計に、今月の直近7日の1日平均 × 残りの日数を足したもの。今月がまだ7日に満たないときは、1日からの日数で平均する |

単価を 0.008 ドルで置くのは、Linux の標準ランナーの単価が 0.006〜0.008 ドルで、高いほうで割ると
段に早めに届くと見積もれるためである。

月末の見込みに先月の分を混ぜないのは、月替わりに入れた削減が見込みに出なくなるためである。
