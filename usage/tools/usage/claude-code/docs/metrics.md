# 指標の定義

[README.md](../README.md) と個人のページに出す項目について、何を数え、何を数えないかを定める。

## 集める項目

| 項目 | 数えるもの | 数えないもの |
|---|---|---|
| トークン量 | Claude Code が API を呼ぶたびに使ったトークン。入力・出力・キャッシュの読み書きを合わせる | ほかの Claude の画面（チャットなど）で使った分 |
| 利用時間 | Claude Code がツールの実行や応答の生成をしていた時間。同時に動かした会話の分は足し合わせる | 人が入力や応答を読んでいた時間（ターミナルでしか記録されず、VS Code 拡張の分と並べられない）。開いたまま放置していた時間 |
| 会話の数 | Claude Code が会話を始めた回数。`--resume`・`--continue` で再開した分も数える | |
| commit | Claude Code が自分で実行した `git commit` の回数 | 人が手で打った commit。GitHub 上の commit 数とは一致しない |
| PR | Claude Code がシェルのコマンドか MCP のツールで作った PR の数 | 人がブラウザなどから作った PR |
| 追加・削除した行数 | Claude Code がファイルを編集して足した行と消した行 | 人が手で編集した行 |
| 立てた Issue | 組織の全リポで、本人が立てた Issue の数。立てた日に数える | PR。GitHub アカウントの対応表（`github.json`）に無い人の分（表には「-」と出る） |
| 閉じた Issue | 本人が立てた Issue のうち、閉じられた数。閉じた日に数え、閉じた人と、完了か取りやめかは問わない | 他人が立てた Issue を本人が閉じた分 |
| 使った場所 | 利用時間を、ターミナル・VS Code 拡張などの起動元ごとに分けたもの | 起動元が記録されない古い版の分は「不明」に入る |
| 使った日数 | 平日のうち、トークンを10万以上使った日の数 | 土日にトークンを使った日。10万に満たない日（起動して設定を確かめただけの日） |
| 費用 | トークンを定価で換算した推定額 | Team プランの実際の請求額 |

## 使い方の項目

| 項目 | 計算 | 読み方 |
|---|---|---|
| スキル | 期間中にスキルを使った回数の合計。`/` で打った分と、Claude Code が自分で呼んだ分を合わせる | 多いほど、繰り返す作業をスキルにして使っている。スキルごとの回数と割合は個人のページに出す。ログが1件も届いていない人は「未取得」と出し、0回と区別する |
| サブエージェントに任せた割合 | サブエージェントの費用 ÷ 全体の費用 | 調べ物やテストの実行などを、別の Claude に任せているか |
| Effort | メインの会話で使った Effort（応答にかける思考量の設定）の段階の数と名前（low・medium・high・xhigh・max） | 1種類なら、作業に合わせて切り替えていない |
| モデル | メインの会話で使ったモデル（系統とバージョン）の数と名前（opus 5.5・sonnet 5.5 など） | 1種類なら、作業に合わせて切り替えていない。古いバージョンが残っていれば別の種類として出る |
| 1会話あたりのトークン量 | 期間のトークン量 ÷ 会話の数 | 大きいほど、1つの会話を長く続けている |

サブエージェントは、Claude Code が仕事の一部を別の Claude に任せる仕組みである。本人とやり取りする
会話をメインと呼んで区別する。任された側は別の会話で動き、結果だけを返すので、調べ物の途中経過で
メインの会話が長くならない。
どのサブエージェントに任せるかは、大半を Claude Code が自動で決める。そのため、種類ではなく割合で見る。

Effort とモデルは、使った種類の数と名前を出す。切り替えているかどうかを見るための項目で、
種類が多いほど良いわけではない。どちらもメインの会話の分だけで数える。サブエージェントと補助の
処理（会話のタイトル付けなど）は、Claude Code が自動でモデルや Effort を選ぶことがあり、本人の選択を
表さないためである。

1会話あたりのトークン量で会話の長さを見るのは、Claude Code が API を呼ぶたびに、それまでの
会話をキャッシュから読み直すためである。会話が長いほど1回に読む量が増え、トークン量が膨らむ。
`/clear` で会話を切り替えたときに会話の数へ入れるかは、Claude Code の文書に書かれていない。
入れないなら、`/clear` で会話を短く切っている人も、1会話あたりのトークン量が大きく出る。

トークン量の9割以上はキャッシュ読み込みなので、トークン量は会話の長さと呼び出しの回数でほぼ決まる。
トークン量が多くても、それだけ仕事を進めたことにはならない。

## 期間の区切り

1日の区切りは日本時間の 0:00 である。土日の記録は、表にも図にも出さない。README.md の図と表は
直近28日の分で、図は日ごとの値、表は期間の合計で出す。期間は、誰かが初めて使った日より前には
遡らない。各メンバーの Claude Code に送信設定が届く前の日は全員が空になり、使わなかった日と
見分けられないためである。
README.md の使い方の表と、個人のページのモデル・Effort・使った場所は、内訳を取り始めた日以降の分だけで出す。
