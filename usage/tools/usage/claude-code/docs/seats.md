# seat の判定

[README.md](../README.md) の seat の表の「要る seat」の決め方と、その基準にする上限の置き方、名簿の書き方を定める。

## 判定の規則

seat の表は、1人ずつ要る seat を決め、その数を合わせて契約する seat の数を出す。ほかのメンバーとは比べない。

利用上限は7日ごとに戻るので、直近2週を7日ずつに分け、それぞれの費用（API の定価で換算した推定額）を
Premium の上限に対する割合で見る。上限は使ったモデルの計算量で減るため、トークン量ではなく費用を使う。
土日に使った分も上限に数えられるので、費用には土日を含める。次の順に決める。

1. 記録が無い人は、使っていないとは決めず、送信設定が届いているかを先に確かめる
2. 記録の期間が2週に満たないあいだは、誰も決めない。期間は誰かが初めて使った日から数える（[metrics.md](metrics.md) の「期間の区切り」）
3. 2週の平日のうち使った日が2日以下（週1日以下）なら、seat は要らない
4. 2週のうち割合の高い方の週で、次のように決める。上限の値は「[上限の置き方](#上限の置き方)」にある

| Premium の上限に対する割合 | Standard の上限に対する割合 | 要る seat |
|---|---|---|
| 20% 以下 | 100% 以下 | Standard |
| 20% を超え 40% 以下 | 100% を超え 200% 以下 | Review |
| 40% を超える | 200% を超える | Premium |

1週だけ休んだり忙しかったりした人を誤って下げないよう、割合の高い方の週で決める。

表で「Review」となる人とは本人と話し、使い方を絞って Standard に収めるか、Premium の上限近くまで使うかを決める。
Premium の費用を払うなら上限近くまで使うのが合理的で、Standard の上限を少し超える程度なら使い方を絞れば
収まる見込みがあるので、境を Standard の上限の2倍に置く。

## 上限の置き方

Premium の7日間の上限は、費用に直して1500ドルと置く（`render.py` の `PREMIUM_WEEKLY_USD`）。
上限はトークン数でも金額でも公表されていない。Premium のメンバーが上限に当たった7日間の費用が
1500ドル前後だったので、その値を100%とした。

Premium の上限は Standard の5倍なので、Standard の上限は Premium の上限の20%になる（`STANDARD_SHARE`）。

Claude Code の `/usage` で7日間の上限の使用率を見て、同じ7日間の費用と並べれば、上限を確かめられる。
費用 ÷ 使用率が、その人の seat の上限になる。使用率を記録として集めない理由は、
[setup.md](setup.md) の「まだ取っていないもの」にある。

## 名簿の書き方

`tools/usage/claude-code/seats.json` に、seat の表と同じ名前（メールアドレスの @ より前）と、seat の種類を書く。

```json
{
  "<名前>": "premium",
  "<名前>": "standard"
}
```

人の出入りと seat の種類の変更のたびに直す。名簿に無い人は判定の列に「名簿に足す」、種類が
`null` の人は「名簿に seat の種類を書く」と出る。
