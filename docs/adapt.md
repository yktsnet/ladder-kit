# 自社へ持ち込む

そのまま使える想定では書いていない。判定文が名指しする置き場と、軸の取り方を差し替える。

## 1. 判定文の置き場を差し替える

[ladder.md](ladder.md) の判定文は `PLAN.md` や `docs/guarantees.md` を名指ししている。
これは [sdlc-kit](https://github.com/yktsnet/sdlc-kit) が置く場所である。別の型を
使っているなら、同じ役割の置き場へ読み替える。

| 判定文が指すもの | 読み替える先 |
|---|---|
| `PLAN.md` の出口 | 着手前に完了条件を書く場所 |
| コミットで止まって裁可を待つ | 裁可の記録が残る場所 |
| `docs/guarantees.md` | 公開面に対する保証を列挙した場所 |
| `docs/ops/` への変更 | 手順そのものを置いた場所 |
| CI 定義とブランチ保護 | そのまま |

**置き場が無い役割は、判定文ごと落とす。** 無い場所を指す判定文は誰に対しても偽になり、
軸の点を不当に下げる。

## 2. 軸を差し替える

A と C は、依頼元と自社が別会社である前提で書いてある。自社サービスを作る組織なら、
依頼元を社内の企画・事業側と読み替えるか、軸ごと組み替える。

B は残す。配られた型に乗れるかを測る軸で、エージェントで開発を回すなら組織の形によらず要る。

## 3. 段階を差し替える

L4・L5 は「案件」を単位にしている。案件で区切らない組織では、
プロダクト・チーム・組織のいずれかに読み替える。刻みの本体は
**任せられる範囲の広さ**であり、単位の名前ではない。

## 書き足すときの規則

軸を足す場合も、次の3つは崩さない。

- **判定文には、リポジトリの何を開けば真偽が分かるかを書く。** 抽象語で書いた時点で、
  採点は評価者の解釈勝負になる
- **観測できていない軸は未観測として残す。** 点で埋めない
- **型が強制しない高さを判定文に書かない。** 書くと、型を回しても誰も届かない段階ができる
